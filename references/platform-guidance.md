# 平台方向与执行规则

## 规划前确认

平台为必填选择：通用电商、淘宝/天猫、拼多多、小红书、抖音电商。用户请求已经明确平台时直接记录；否则一次简短询问并等待回答，不自动选择通用。识别同义名称后使用平台方向表对应 ID。用户提供了商品资料，也不能替代平台确认。

## 完整方向

| 平台 | 规划与设计重点 | 内容边界 |
|---|---|---|
| 通用电商 | 根据品类确定商业美术方向；商品主导封面、互补主图、变化丰富的连续详情，手机端层级清晰 | 保留真实购买任务与必要参数 |
| 淘宝/天猫 | 清晰主图、功能特写、使用场景、已确认规格，详情保持一致的纵向节奏 | 商品叙事和规格证据完整 |
| 拼多多 | 商品利益点一眼理解、大字易读、商品展示直接 | 禁止虚构低价和促销 |
| 小红书 | 生活方式编辑式画面、自然使用场景、简洁口语文案 | 禁止虚构个人使用经历和背书 |
| 抖音电商 | 手机端快速理解、强商品焦点、短标题、依据已知事实的视觉演示 | 禁止编造功能或演示结果 |

实际执行取 platform-directions.json 的完整 direction；不是只传中文标签。平台方向与品类、品牌定位、用户视觉偏好一起作用，不能套固定构图，更不能删必要描述、规格、尺码或用户指定文字。

## 贯穿阶段

1. 规划前确认平台；将 platformContext 放入内容策略输入，确定符合目标平台的购买问题、叙事、信息表达和文案语气。
2. 设计整套时再次传入同一平台及完整方向，将其落实到机位、构图、视觉证明、文字层级和连续详情，而不只写“适合某平台”。
3. 独立方案审查核对平台方向，同时保留全部既有事实、信息覆盖、排版、节奏和参考角色校验。
4. 编译器在完整逐图设计提示词后附平台方向、语言和比例。用完整编译结果生成，不能漏掉平台后缀。
5. 逐图与整套复查判断实际成图是否落实目标平台表达；若有具体问题先反馈，由用户决定修改。

默认电商套图主图 1:1、详情 3:4，平台选择不会自动切换比例。小红书方向在这里用于商品套图，不自动切换为独立笔记、标题正文标签工作流。需要其他比例、投放位置或独立创作类型时先明确范围，再处理对应合同，不能暗自修改。

以上是创意方向，不代表已满足全部最新上架要求。用户要求可直接上架或指定具体限制时，核对对应平台官方现行规范或用户提供的明确规格；缺失的关键要求先问，不凭记忆保证合规。确认后的约束写入实际需求并贯穿设计和复查。
